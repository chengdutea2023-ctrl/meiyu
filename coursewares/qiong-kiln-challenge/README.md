## 操作流程

1. 预测训练后的 AI 是否一定优于固定程序。
2. 手动用加热、保持、降温完成一窑；损坏或烧成不足也保留记录。
3. 观察固定规则自动运行；一键进行同条件 30 窑测试。
4. 选择奖励或调整滑块，从零训练 300/1000/3000/8000 轮；过程可停止，保留实际已学策略。
5. 观察已训练 AI 的逐步动作及 Q 值，再改变奖励做第二组训练。
6. 比较实际数据、写发现和解释、回答概念题，完成报告。

先预测、比较与写报告的顺序不强制锁定，提交时检查完整性。合格与失败都算一次实验；必须完成三种模式、两组不同奖励对照、预测、至少 5 字发现与解释以及概念题。评价总分 100，其中实验与解释完成占 80，概念题占 20；模拟器合格率不直接决定成绩。仅做基础完整性检查，不宣称自动理解文字质量。

## 模拟和算法

- 热度是 0–100 指数，初始 20；加热 +18、保持 −2、降温 −16，各步叠加均匀的 ±2 扰动。
- 热度 58–80 时烧成进度增加 1；累计 3 后降到 ≤35 合格。≥94 过热损坏，22 步截止。累计进度不因中途离开区间清零。
- 加热/保持/降温分别消耗 5/2/0 个能量单位。
- 每步奖励：`−能耗×能耗权重−耗时权重+新增烧成进度×合格奖励×0.08`；最终合格追加合格奖励，过热扣损坏惩罚，超时扣损坏惩罚的一半。过程奖励有明确说明。
- 状态为热度按 5 取整、烧成进度、操作步数；3 个动作；Q 表从 0 开始。更新为 `Q(s,a) += 0.24*(reward+0.97*maxQ(s',*)−Q(s,a))`，终止状态未来价值置 0。
- ε 从 0.9 递减至约 0.08，探索和并列动作均使用带种子的随机数。每轮的窑炉和动作随机种子独立派生。
- 训练窑炉种子为 `815+67*i`（最多8000轮），统一测试使用另一组 `1330001+47*j` 的30个种子，两组完全不重叠。测试不更新 Q 表，也不主动探索，未知状态及并列动作随机选择。
- 固定程序和各 AI 测试使用相同 30 个测试种子。单窑记录单独列出，不把一次成功当稳定合格率。不同奖励配置下的“平均奖励”不可直接横向比较。
- 每次训练真正执行状态转移及 Q 更新。曲线是每50轮的实际训练合格率，包含探索，因此与独立测试率不同。训练不保证成功或优于固定程序。
- 标准“重视节能”预设会展示奖励失衡下不加热的失败策略；不隐藏失败。可调整合格奖励、能耗权重和训练轮数继续实验。

算法参考：[Farama Gymnasium 的 tabular Q-learning 教学](https://gymnasium.farama.org/tutorials/training_agents/frozenlake_q_learning/)。本实现为独立 JavaScript 模拟，未引入 Gymnasium 运行依赖。

## 智课接入与保存

STATIC 类型，所有素材、脚本本地捆绑，无 CDN、摄像头或付费调用。读取 `launchToken`、`platformApiBase`、`returnUrl`；先 verify，再 STARTED，重要节点 PROGRESS。没有有效入口时拦截互动。

完成时冻结本次报告，先上传 TXT 报告和 JSON 数据，再提交 COMPLETED，等待成功后开放正常返回。JSON 包含动作轨迹、奖励、曲线、每组 Q 表、同一种子下学习前后的策略回放及测试统计；摘要使用平台现有 `displayTitle/brief/scoreText/resultItems/processSummary/artifacts` 字段，教师与学生默认展示可读取。失败停留在报告页重试，只补传失败附件，避免重复完成。无生产域名、固定身份、密钥或数据库连接。

已完成真实本地平台验收：学生后台启动、断网后的保存重试、教师和学生成绩页、默认投屏、TXT/JSON 下载均通过。生产上传与线上验收仍需有效管理员及隔离测试会话，当前不能称为正式上线。
