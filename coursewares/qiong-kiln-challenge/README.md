## 2.0.0 五选三示范学习

保留“我来烧”，将两种奖励偏好替换为“从五类完整示范中选三类 → AI参考经验 → 自主试错 → 比较两套组合”。五类为稳火保温、猛火冲刺、省火低烧、提前收火、反复调温。示范曲线来自真实模拟，不按名称预设成败。必须完成两套不同组合，选择顺序不影响组合身份；重复同一组合更新展示、保留历史，但不增加完成数。更换选择会清除当前可运行模型，要求重新学习。

每类在同样的20个窑况中提供示范，合计60次；来自教学脚本，不是学生亲自采集的数据。AI从空Q表开始，对真实状态/动作/奖励/下一状态经验进行5遍固定种子的打乱学习，再自主试错300轮。两套组合共用合格100、损坏80、能耗1、耗时1的反馈参数及现有Q-learning公式；不再开放奖励滑块或训练轮数选择。示范后和练习后均在同组100个独立窑况中测试，测试不更新Q表。示范种子为2500001+79*i（20个），打乱种子733，自主练习种子815+67*i（300个）；与测试种子1330001+47*j互不重叠。

同一模拟、同一预算下，本轮示例“稳火/猛火/低烧”从示范后的68%到练习后的91%，平均能耗28.3；“猛火/提前收火/反复调温”从1%到29%，平均能耗39.8。这些是实际模拟结果，不是UI常量或保底概率；不要求10种组合最终各不相同，结果相同也照实展示。失败计入平均能耗，失败经验也可能帮助学习。教学重点是示范影响学习起点、反馈帮助调整、控制条件检验效果，不宣称观看动画即掌握算法。

保留手动风险、烟火、音效和AI单窑约30秒的独立视觉演示。完整实验50分，五题各10分；新版题目覆盖示范、动作、反馈、公平比较和相近结果。报告与summary标记`lessonFlow: manual-demonstrations-ai`、`demonstrationVersion: demonstrations-v1`；每次实验保存组合ID、选择、示范来源/种子、实际经验更新数、阶段结果、Q表及真实策略回放。示范原始轨迹/经验按类型在顶层`demonstrationLibrary`去重保存，重复学习不复制整套示范。完整JSON不塞进平台summary。

## 1.9.0 同组窑况与学习证据

AI采用版本化教学模型`variable-kiln-v1`：两种奖励共用散热、温度和烧成进度波动，不给节能模式单独加失败概率。学生选择奖励后，AI仍从零进行真实Q-learning；画面显示实际“看到的温度/进度 → 选择的动作 → 进度反馈与奖励”。训练完成后，使用同组100个未参与训练的窑况测试；失败窑照常计入平均能耗，同时计算每件合格品分摊能耗。结果由实际模拟得到，不预设成功率，也不承诺节能必然降低合格率。

默认3000轮的本轮可复现实测：烧好100/100窑、平均能耗28.3；节能95/100窑、平均能耗27.3。后者每窑约省3.5%，但失败损耗计入后，每件合格品能耗从28.3变为28.7。仅为该版本、该训练设置及测试样本的结果，不是现实窑炉结论或固定概率。额外300个独立窑况也验证两策略的差异，不从结果中挑选展示样本。

学习主线：先预测哪种方案更稳，再观察状态、动作和反馈，最后用相同测试条件比较取舍，并选出自己的发现。教学目标是理解人设目标、AI试错学习、用对照证据判断策略；观看动画不等于掌握Q-learning公式。第四题同步改为比较同条件的合格数量与能耗，不暗示两组必须100%或节能必须失败。仍是两个环节、50分实验加五题各10分，失败计完成，手动风险和AI单窑30秒演示不变。

JSON/TXT保存模型版本、条件范围、100个测试种子、成功/失败数量、失败原因、实际决策及能耗口径，系统解释不冒充学生回答。默认无profile的旧引擎仍可复现历史30窑结果，旧报告和成绩不重写。以下旧版说明为历史记录，与本段冲突时以1.9.0为准。

## 1.7.1 温控风险与重新点火

仅手动实时模型增加温控风险：模拟1350℃以上连续2秒触发一次炸膛，结束本窑，伴随短暂尘烟、碎屑、轻微震动及低沉音效；短时高温及时降温可以恢复。升温达到600℃后，未烧熟时低于300℃连续3秒会熄火；停止加热消耗，5秒冷却结束后点击“重新点火”继续。连点不能跳过或重置冷却。初始冷窑、已烧熟的正常出窑降温不会误判熄火。后台、指南或离开窑场暂停冷却计时，点击降温恢复；重新开窑清除风险状态。均为教学游戏规则，不代表真实窑炉操作或安全指导。

AI引擎、奖励和五题评分不变。新JSON保存`hazardVersion: hazards-v1`、熄火/重燃/炸膛事件及模拟时间，TXT以中文呈现；历史记录不改写。音效服从静音、后台和弹窗状态，每窑只播放一次；减少动态效果下无震动。以上持续高温规则替代1.7.0的即刻损坏阈值，原玩法仍可约30秒完成。

## 操作流程

1. 入口验证后阅读两步说明，点击开始实验。
2. 手动用持续加热、降温完成一窑；损坏或烧成不足也保留记录。
3. 进入教AI烧，从五类示范中选三类，学习并观察AI真实动作与反馈。
4. 点击“选择第二轮策略”，在弹窗中至少替换一类并点击“开始第二轮学习”；第二轮后点击“选择第三轮策略”，选择未完成过的组合并开始学习。比较三套组合的阶段结果及平均能耗。
5. 完成2/2后选择发现、回答五道题并提交；每题答对得10分。

提交检查手动记录、三套不同组合、发现选择和五道题全部作答。合格与失败都算实验；评价总分100，实验占50、五题每题答对10分，模拟器合格率不直接决定成绩，不宣称自动理解文字质量。自主练习固定300轮，提前停止保留真实记录但不计一套完整组合；已有模型仍可观察，不将其标为完整训练。

## 模拟和算法

- 手动采用独立实时模型，规则见1.7.0/1.7.1；不与AI作同条件竞赛。以下为AI离散教学模型。
- 热度是0–100指数，初始20；加热+18、保持−2、降温−16。新模型每窑散热0–2、每步温度扰动±6，烧成效率0.8–1.2；条件由种子生成，与奖励和动作选择随机数独立。
- 热度58–80时有机会增加1烧成进度，概率随区间内热度及本窑效率变化；两种奖励共用同一函数，按模拟步抽取同一外部进度随机流。累计3后降到≤35合格，≥94过热损坏，22步截止。累计进度不因离开区间清零；进度并非进入烧成区就必加1。
- 加热/保持/降温分别消耗 5/2/0 个能量单位。
- 每步奖励：`−能耗×能耗权重−耗时权重+新增烧成进度×合格奖励×0.08`；最终合格追加合格奖励，过热扣损坏惩罚，超时扣损坏惩罚的一半。过程奖励有明确说明。
- 状态为热度按 5 取整、烧成进度、操作步数；3 个动作；Q 表从 0 开始。更新为 `Q(s,a) += 0.24*(reward+0.97*maxQ(s',*)−Q(s,a))`，终止状态未来价值置 0。
- ε 从 0.9 递减至约 0.08，探索和并列动作均使用带种子的随机数。每轮的窑炉和动作随机种子独立派生。
- 自主练习种子为`815+67*i`（当前固定300轮），测试使用另一组`1330001+47*j`的100个种子，与示范、练习完全不重叠。测试不更新Q表，也不主动探索，未知状态及并列动作随机选择。
- 组合间保持相同模型、反馈、练习预算和测试窑况；报告保存版本及样本组ID。隐藏的历史固定程序仍使用旧模型30窑，仅用于兼容。单窑记录不代表稳定合格率。
- 每次训练真正执行经验更新和状态转移。曲线是每50轮自主练习的实际合格率，包含探索，因此与独立测试率不同。学习不保证成功或优于其他组合。
- 历史奖励参数和旧引擎仍可复现旧数据，但不再作为当前课堂的可选方案；当前统一反馈不因示范组合变化。

算法参考：[Farama Gymnasium 的 tabular Q-learning 教学](https://gymnasium.farama.org/tutorials/training_agents/frozenlake_q_learning/)。本实现为独立 JavaScript 模拟，未引入 Gymnasium 运行依赖。
