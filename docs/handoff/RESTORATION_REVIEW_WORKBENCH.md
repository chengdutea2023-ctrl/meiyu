# 修复课件教师审核工作台

2026-11-03。仅调整邛窑 AI 修复挑战的课外资料审核界面，不修改服务端、平台 API、数据库、账号、教学任务、成绩、学生作品或付费额度。

## 日常操作

1. 从教师平台进入该课件的资料审核，默认查看待审核学生。
2. 左侧选择学生，右侧直接查看本次线索图片、来源和学生发现；图片可以放大。
3. 通过并查看下一位；需要补充时，选择常用原因或填写反馈后退回并查看下一位。
4. 时间和准备要求在“准备设置”；个人补交、审核反馈及排除/历史资料在学生标题旁的更多菜单。

已通过、待补充、未提交和全部学生均保留入口；手机使用学生下拉列表和可展开姓名搜索。准备截止不自动开课或结课，仍在原教师平台控制。

## 安全和兼容

- 审核仍携带当前学生、revision 和 evidenceDigest，服务端原有教师/任务权限校验不变。
- 快速切换学生时，过期的详情响应和照片不会覆盖当前学生。
- 只有确认审核保存成功并刷新名单后才跳到下一位，不批量通过其他学生。
- 失败或版本冲突不自动重试写请求，不跳人；保存已成功但刷新失败时保留确认状态并提示刷新。
- 图片未完整加载不能通过，但可退回补充；单张图片支持重读。
- 学生上传、线索编辑/排除/重新采用、提交/撤回、反馈和补交流程保留，旧资料不转换、不删除。
- 设置弹窗保留北京时间、开始/截止时间、要求、常规上传开关和个人补交截止。键盘焦点约束及 Escape 关闭不替代权限控制。

## 最小发布

只发布修复课件，使用独立映射避免触碰其他课件：

```sh
node scripts/courseware-sync.mjs --root /opt/zhimei-education-platform/courses --mapping ops/qiong-restoration-deployments.json --catalog coursewares/incoming-qiong-restoration.json
```

GitHub 主线快进、`deploy:preflight`、生产干净检查和数据库备份通过后，追加 `--apply --backup /var/backups/zhike/<unique-release>/changed-source-files`。发布前另备份整个 `static` 目录和入口文件，并先从已验证 Git 版本将新散列资源复制到运行目录的 `static/app`（不覆盖同名旧资源），再同步入口；保留旧散列资源、运行数据及私密配置。

本次无服务端变更，不重启课件、主 API 或 Nginx。同步后再次检查零差异，核对公共入口及 JS/CSS 的 SHA256、服务健康、主线提交。回滚时从该次私密备份恢复匹配静态入口及变更文件；没有迁移，不恢复数据库、不覆盖发布后教学数据。

实测边界：本地模拟完整审核与真实后端既有集成测试；生产不代教师审核真实学生，不用修改教学数据来做 UI 验收。在线正式教师登录后的人工验收仍需在原教学任务中完成。
