## 实现与评价

先预测、手动试烧、观察固定规则、真实Q-learning训练、修改奖励再训练、比较并提交。奖励配置改变后旧模型不可直接运行，需要重新训练。训练、测试、动作轨迹及Q表均由实际模拟生成，不保证AI成功或优于固定程序。

热度0–100、烧成规则及能耗均为教学模拟。课程不使用摄像头、外部AI服务或真实烧制参数。报告评价为实验完整性80分、概念题20分，不按窑炉合格率评分，也不宣称自动理解文字质量。

提交先上传TXT报告及完整JSON，再上报COMPLETED；失败保留同一报告快照，成功附件重试不重复上传。摘要兼容现有教师、学生和默认投屏界面，无数据库迁移或平台公共API变更。未提交内容保存在当前页面内存中，刷新前应导出或提交。

## 打包与发布步骤

1. 使用独立功能分支；不覆盖主目录其他课件的未提交修改。课件目录清单为 `coursewares/incoming-qiong.json`，独立运行映射为 `ops/qiong-courseware-deployments.json`。
2. 在干净提交上执行 `npm run coursewares:qiong:package`。输出 `output/qiong-kiln-release/`：1.0.0最小ZIP、自包含离线HTML、release-manifest、release-info及SHA256SUMS。ZIP仅含manifest、README、static和图标许可，测试及工具不进入上传包。
3. 对源目录和ZIP执行接入规范的portable validator，核对Git提交及SHA256。
4. 推送并对齐干净main，运行 `npm run deploy:preflight`；生产检查版本可快进、服务健康和磁盘。先通过项目标准备份脚本生成有效数据库备份，记录发布前提交和新登记对象。
5. 只读查询课程和课件冲突。若同名课程已由其他邛窑课件建立，复用该容器；slug与本清单不同则先更新清单、映射并重新提交打包，不能建立重复课程。
6. 生产源码只快进到已验证Git提交，使用平台标准课程/课件登记和ZIP上传接口发布；不得直接拷贝本地目录覆盖运行目录。
7. 使用标准登录和平台接口建立隔离测试任务，完成线上学生进入、保存、教师/学生记录及附件验收，关闭该测试任务。无需重启主API、修改Nginx或执行数据库迁移。

本地接口验收辅助工具：

```sh
node scripts/qiong-kiln-acceptance.mjs setup <API_BASE> <PRIVATE_ACCOUNTS_JSON> <PRIVATE_RECEIPT_JSON> <ZIP>
# 在真实学生浏览器中完成报告后：
node scripts/qiong-kiln-acceptance.mjs verify <API_BASE> <PRIVATE_ACCOUNTS_JSON> <PRIVATE_RECEIPT_JSON>
node scripts/qiong-kiln-acceptance.mjs close <API_BASE> <PRIVATE_ACCOUNTS_JSON> <PRIVATE_RECEIPT_JSON>
```

生产必须先完成备份与发布门禁，再使用上述工具；工具不代替备份，不生成伪造学习报告，不读取数据库。
