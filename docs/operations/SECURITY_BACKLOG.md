# 依赖安全升级清单

最后审计时间：2026-08-23。

```bash
npm audit --omit=dev
```

当前生产依赖审计报告为 14 项：3 个低风险、2 个中风险、9 个高风险、0 个严重风险。现有构建和运行验证通过，但这些问题不能因“系统能运行”而忽略。

## 优先级一：上传与外部输入

- `adm-zip < 0.6.0`：恶意 ZIP 可能触发超大内存分配。课件 ZIP 上传必须继续受体积限制，并安排升级到 0.6.x 后做上传、解压和路径穿越回归测试。
- `multer < 2.2.0`：复杂字段和中断上传可能造成拒绝服务。随 `@nestjs/platform-express` 的安全版本升级，回归大文件、中断和嵌套字段。
- `xlsx`：npm 当前版本存在原型污染和 ReDoS，审计没有可用修复。学生导入接口必须限制文件大小、行数和处理时间，并评估 SheetJS 官方新版本或替代解析库。

## 优先级二：服务端依赖

- `nodemailer`：当前版本涉及地址解析、SMTP 参数和文件/URL 访问风险。升级可能跨主版本，应在邮件重置流程、TLS、收件人解析和附件限制回归后发布。
- `@nestjs/swagger` / `js-yaml`：升级到带修复的兼容版本，并验证 Swagger 文档生成。
- `body-parser`、`qs`：随 Nest/Express 依赖树升级，保留明确的请求体大小限制。

## 优先级三：构建工具

- `vite`、`esbuild`、`postcss`、`@babel/core`、`nanoid` 的报告主要涉及开发服务器、构建输入或特定调用方式。仍应升级，但不得在生产服务器开放 Vite 开发服务。

## 升级规则

1. 每类依赖单独分支和提交，不执行 `npm audit fix --force`。
2. 升级后运行 `npm run agent:check`，并回归登录、文件上传、学生导入、密码重置和课件部署。
3. 记录升级前后审计数量及不可修复项。
4. 高风险上传接口在完成升级前保持认证、文件大小、扩展名和服务器端解析限制。
