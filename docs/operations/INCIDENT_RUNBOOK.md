# 故障处理手册

## 处理顺序

1. 记录发生时间、用户、入口、课件、操作步骤和截图。
2. 检查公共入口与 `/api/health`。
3. 检查磁盘、内存、服务状态、监听端口和最近日志。
4. 区分平台 API、数据库、Redis、静态文件、课件 Node 服务和第三方 AI 接口故障。
5. 修复前保留日志与当前提交号；高风险操作先备份。

## 平台不可用

```bash
systemctl status meiyu-api nginx postgresql redis-server --no-pager
ss -lntp
df -h
journalctl -u meiyu-api --since "30 minutes ago" --no-pager
nginx -t
```

健康检查中 `database` 或 `redis` 为 `down` 时，先修复依赖，不要反复重启所有服务。

## 四格漫画生成失败

1. 记录失败时间、学生任务 ID、主题、风格、前端显示进度和错误请求 ID。
2. 查看平台 API 日志及四格漫画独立 Node 服务日志。
3. 检查 AI 文本/图片接口的超时、限流、内容审核、返回结构、下载失败和密钥有效性。
4. 确认四张图的任务状态。部分图片成功时保留已生成结果，不删除学生作品。
5. 重试只处理失败分镜，并设上限和退避；同一请求不得无限循环。
6. 若业务规则要求四张全部成功才能提交成绩，界面仍应展示已完成分镜并允许继续重试。

禁止在日志中记录 AI API 密钥、完整学生身份令牌或生产环境变量。

## 动态课件异常

```bash
systemctl list-units --type=service --all | grep -i course
ss -lntp
journalctl -u <courseware-service> -n 200 --no-pager
```

确认 systemd 服务、工作目录、端口和 Nginx/API 转发一致。端口以线上实际配置为准。

## 数据库或磁盘异常

- 磁盘超过 80% 时先找日志、旧构建和过期备份，不删除未知业务数据。
- 数据库异常先备份可读数据和日志，再决定重启或恢复。
- 恢复前核对备份时间、数据库名和迁移版本，并停止应用写入。

## 收尾

恢复后完成登录、课件启动、成绩保存和三个入口验收，记录根因、修改提交、部署时间、回滚点和后续预防措施。
