# 提交详情只显示图片附件

2026-10-25：教师提交统计和学生记录共用的详情页，其“作品与附件”仅展示图片。上传附件按MIME筛选，兼容历史摘要中的图片字段；TXT、JSON、ZIP、HTML、音频和视频不渲染卡片或空白占位。没有图片时整块隐藏。

详情下方摘要不再重复列出`artifacts`、`savedArtifacts`、`artifactUrl`、`audioUrl`、`recordingUrl`等文件元数据。分数、学习结果、过程摘要等教学信息不变。过滤仅作用于渲染：接口原始附件、文件、成绩、历史提交与投屏输入不改动；投屏仍可读取报告JSON和原始文件。

`scripts/record-images.test.mjs`使用真实组件源码进行渲染回归，覆盖混合附件、纯文件、无附件、历史图片、MIME判断和输入不被修改，已加入`npm run coursewares:test`。发布前执行`npm run agent:check`及`npm run deploy:preflight`；浏览器分别核对师生详情、图片正常加载、无图隐藏及原有投屏。

本地验收：完整检查及5项新增测试通过；师生两种身份各在1440×900、1024×768、768×1024、390×844验证混合附件仅1张图片、纯文件无附件区、历史摘要图片可见。详情抽屉无横向溢出、无脚本错误、模拟接口无写入；两种身份均实际打开烧窑投屏，隐藏的JSON仍能正常读取并显示实验对比。证据在`/private/tmp/record-images-browser-qa/`，仅合成数据；未改变原教师工作台窄屏布局，也未把该背景页面的布局问题计入本次修复。

仅发布后台前端，不同步课件运行文件、不修改数据库、不重启API或课件服务。先备份数据库和后台dist，在生产干净main上构建至私密暂存目录；保留旧哈希资源，最后原子替换入口HTML。回滚恢复备份的后台入口及对应资源，不恢复数据库覆盖新提交。已经打开的后台需刷新后重新打开详情。
